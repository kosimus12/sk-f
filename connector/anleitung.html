SK Connector · Einrichtung

Beide Macs anbinden

Ein Abend, zwei Rechner, drei Ziele. Die Reihenfolge ist wichtig: ohne Hub geht auf den Macs nichts.

  1. Lesen und Schreiben auf beiden Macs, auch wenn der Mac gesperrt ist
  2. Browser-Steuerung auf beiden
  3. Zugriff auf alle Programme auf beiden

00 Jetzt sofort, vor allem anderen

Bei deinem DNS-Anbieter

A-Record auf die Hetzner-IP setzen

Eine Subdomain, z. B. hub.sk-finanzberatung.de. Die Propagation dauert manchmal eine halbe Stunde — deshalb zuerst.

dig +short hub.DEINE-DOMAIN.de

Muss deine Hetzner-IP zeigen, bevor du weitermachst.

01 Hub auf dem Hetzner

Hetzner · SSH

Installieren

git clone https://github.com/kosimus12/sk-f /opt/src/sk-f
cd /opt/src/sk-f
git checkout claude/hetzner-multi-device-connector-ply62n
cd connector

sudo bash hub/deploy/install.sh

Der Installer zeigt einmalig das Control-Token (skc_ctl_…). Sofort in den Passwortmanager — es ist der Generalschlüssel zu beiden Macs und taucht nie wieder auf.

Hetzner · SSH

TLS über Caddy davorsetzen

sudo apt install -y caddy
sudo cp hub/deploy/Caddyfile /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile     # hub.example.de → deine Subdomain
sudo systemctl reload caddy

curl -s https://hub.DEINE-DOMAIN.de/healthz

Erwartet: {"ok":true,…}

Hetzner · SSH

Steuerseite konfigurieren

export CONNECTOR_HUB_URL=https://hub.DEINE-DOMAIN.de
export CONNECTOR_CONTROL_TOKEN=skc_ctl_...

Gilt für alle weiteren Befehle mit skconnect.py.

02 Dein Mac

Hetzner · SSH

Gerät anlegen

python3 tools/skconnect.py add mac-simon "Simons Mac" macos \
        --owner simon --mode full \
        --caps shell,fs,notify,probe,app,browser,mail

full = lesen und schreiben. app ist die Fähigkeit für „alle Programme“. Der Befehl gibt einen Enrollment-Code aus, 30 Minuten gültig.

Am Mac · Terminal

Agent installieren

git clone https://github.com/kosimus12/sk-f ~/src/sk-f
cd ~/src/sk-f
git checkout claude/hetzner-multi-device-connector-ply62n
cd connector

sudo bash agent/macos/install.sh \
     --hub https://hub.DEINE-DOMAIN.de \
     --code skc_enr_... \
     --keep-awake

Beim MacBook, das mit geschlossenem Deckel am Strom hängt, stattdessen --keep-awake-aggressive.

Am Mac · ohne sudo

Freigaben erteilen

Der Schritt, an dem die meisten Setups scheitern. Muss in der grafischen Sitzung laufen, nicht über SSH, und ohne sudo.

bash agent/macos/grant-permissions.sh
  • „Terminal“ möchte „Mail“ steuern. — Erlauben
  • „Terminal“ möchte „Safari“ steuern. — Erlauben
  • … ebenso Chrome, Finder, Notizen, Kalender, Kontakte, Erinnerungen, Nachrichten, Musik, System Events

Warum jetzt und nicht später: macOS fragt bei jedem Programm genau einmal. Kommt diese Frage später, während der Mac gesperrt ist und niemand davorsitzt, kann sie niemand wegklicken — das Kommando scheitert dann einfach. Weitere Programme: --apps "Pages,Numbers,Notion"

Am Mac · Menüleiste

JavaScript aus Apple Events erlauben

Dafür gibt es keinen Dialog — ohne diese Einstellung kommt Seitentext leer zurück.

  • Safari: Einstellungen → Erweitert → „Funktionen für Webentwickler anzeigen“, dann Menü Entwickler → „JavaScript aus Apple Events erlauben“
  • Chrome: Menü Darstellung → Entwickler → „JavaScript über Apple Events zulassen“
Am Mac · Systemeinstellungen

Festplattenvollzugriff eintragen

Sonst sind Dokumente, Schreibtisch, Downloads und die Mail-Ablage für den Dienst leer.

  • Systemeinstellungen → Datenschutz & Sicherheit → Festplattenvollzugriff
  • „+“ anklicken, dann Cmd+Shift+G und beide Pfade eintragen
/bin/bash
/usr/bin/python3
Hetzner · SSH

Gegenprobe

python3 tools/skconnect.py devices
python3 tools/skconnect.py permissions mac-simon

Erst weitermachen, wenn nichts mehr auf FEHLT steht.

03 Katyas Mac

Identischer Ablauf mit --mode full, also lesen und schreiben wie auf deinem eigenen Mac.

Hetzner · SSH

Gerät anlegen

python3 tools/skconnect.py add mac-katya "Katyas Mac" macos \
        --owner katya --mode full \
        --caps shell,fs,notify,probe,app,browser,mail
An Katyas Mac

Agent installieren und freigeben

git clone https://github.com/kosimus12/sk-f ~/src/sk-f
cd ~/src/sk-f && git checkout claude/hetzner-multi-device-connector-ply62n
cd connector

sudo bash agent/macos/install.sh \
     --hub https://hub.DEINE-DOMAIN.de --code skc_enr_... --keep-awake

bash agent/macos/grant-permissions.sh

Danach dieselben zwei Handgriffe wie oben: JavaScript aus Apple Events und Festplattenvollzugriff.

Gemeinsam mit Katya

Drei Befehle zeigen

full heißt Shell-Zugriff, Dateien schreiben, Programme steuern, Mails lesen — derselbe Zugriff wie auf deinem eigenen Mac. Diese drei Befehle gehören zur Einrichtung, nicht als Nachtrag hinterher.

# Was wurde auf meinem Mac gemacht?
python3 tools/skconnect.py audit --device mac-katya --limit 100

# Sofort abklemmen, von überall, wirkt in Sekunden:
python3 tools/skconnect.py revoke mac-katya

# Endgültig entfernen, direkt am Mac:
sudo launchctl bootout system/de.skfinanzberatung.connector

Falls sie erst mal nur mitlesen lassen will: skconnect.py mode mac-katya readonly — jederzeit wieder auf full umstellbar.

04 Browser: die zwei Wege

Du willst beide — sie lösen verschiedene Probleme.

Auf beiden Macs

Weg A — Claude in Chrome, das Add-on

Anthropics eigene Erweiterung, seit dem 26. August 2026 auf allen bezahlten Plänen verfügbar.

  • Claude in Chrome installieren (Version 1.0.36 oder neuer)
  • In der Erweiterung mit dem Claude-Konto anmelden
  • In Claude Code auf diesem Mac: claude --chrome, oder einmalig /chrome → „Enabled by default“

Claude kann dann Tabs öffnen, klicken, tippen, Konsole und DOM lesen — mit deinem eingeloggten Browserzustand, also auch in Gmail, Notion oder Google Docs. Voraussetzung: Anmeldung über /login, nicht per API-Key.

Was es nicht ist: kein Fernzugriff. Es läuft, während auf diesem Mac eine Claude-Code-Sitzung offen ist — nicht, wenn der Mac gesperrt im Nebenzimmer steht.

Schon fertig nach Teil 02/03

Weg B — Browser über den Konnektor

Der Fernzugriff: funktioniert bei gesperrtem Bildschirm, aus einer zentralen Sitzung, für beide Macs gleichzeitig. Läuft über AppleScript und ist mit Teil 02 bereits eingerichtet.

  • browser_tabs — offene Tabs mit Fenster- und Tab-Nummer
  • browser_read — sichtbarer Seitentext
  • browser_open — URL in neuem Tab
  • browser_js — JavaScript im Tab ausführen

Weniger komfortabel als Weg A — kein Klicken per Beschreibung, keine Screenshots. Dafür aus der Ferne und ohne offene Sitzung auf dem Zielrechner.

05 Claude den Konnektor geben

Auf deinem Arbeitsrechner

MCP-Server eintragen

In ~/.claude/mcp.json, danach einmalig pip install -r mcp-server/requirements.txt.

      }
    }
  }
}

06 Abnahme

Sperr beide Macs mit Ctrl+Cmd+Q — sperren, nicht abmelden — und lass sie am Strom. Dann für mac-simon und mac-katya:

Hetzner · SSH

Ziel 1 — Lesen und Schreiben bei gesperrtem Mac

python3 tools/skconnect.py run mac-simon 'whoami && ls ~/Documents | head -5'
python3 tools/skconnect.py run mac-simon 'echo "Test $(date)" > ~/Documents/connector-test.txt'
python3 tools/skconnect.py run mac-simon 'cat ~/Documents/connector-test.txt'
python3 tools/skconnect.py run mac-simon 'rm ~/Documents/connector-test.txt'

Bleibt ls ~/Documents leer, obwohl da etwas liegt: Festplattenvollzugriff fehlt.

In Claude Code

Ziel 2 — Browser bei gesperrtem Mac

  • „Zeig mir die offenen Tabs in Safari auf mac-simon.“
  • „Lies den Text der aktiven Seite auf mac-simon vor.“

Kommt der Text leer zurück: „JavaScript aus Apple Events“ fehlt.

In Claude Code

Ziel 3 — Alle Programme bei gesperrtem Mac

  • „Welche Programme laufen gerade auf mac-simon?“
  • „Lies mir die Titel meiner letzten Notizen von mac-simon vor.“

Fehler -1743 bedeutet immer: für dieses Programm fehlt die Automation-Freigabe.

Wenn etwas klemmt

SymptomUrsacheBehebung
Gerät bleibt offline Daemon läuft nicht tail -50 /var/log/skconnector/agent.log
Fehler -1743 Automation-Freigabe fehlt grant-permissions.sh --apps "Name" am Mac, ohne sudo

Nachts nicht erreichbar Mac schläft pmset -g custom prüfen, ggf. --keep-awake-aggressive

Alles sofort anhalten — skconnect.py killswitch on

Zwei Dinge bleiben bewusst aus, bis du sie ausdrücklich einschaltest: Mailversand (lesen und Entwürfe gehen, echter Versand braucht --allow-mail-send) und die direkte iPhone-Anbindung (für Dateien reicht der Weg über iCloud und den Mac).

Nach ein paar Tagen ins Protokoll schauen: skconnect.py audit --limit 100. Dort steht jedes Kommando mit Zeitstempel — auch jedes abgelehnte.
